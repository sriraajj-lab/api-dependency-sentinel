# Design-Partner Prospect Research

This file records only public, product-level qualification signals. It does not assert that any prospect has a specific unobserved production risk, and it does not contain personal contact data.

| Candidate | Public integration signal | Why it fits the initial outreach hypothesis | Source |
|---|---|---|---|
| n8n | Its official integration page documents OpenAI and Twilio workflow support, including OpenAI actions and Twilio call/SMS operations. | A developer-facing workflow platform with multiple provider surfaces is an appropriate conversation about source-to-code change review. | [n8n OpenAI + Twilio integration](https://n8n.io/integrations/openai/and/twilio/) |
| Activepieces | Its official Stripe page lists webhook-like triggers for payment, customer, subscription, refund, dispute, and checkout events, plus Stripe API actions. | A workflow platform exposing numerous Stripe surfaces can help test whether structured source changes map to the right implementation owner and code area. | [Activepieces Stripe integration](https://www.activepieces.com/pieces/stripe) |
| Pipedream | Its official documentation describes a developer toolkit for customer-facing integrations and a source-available GitHub component registry. | The combination of large integration surface and public component development makes a narrowly scoped conversation about upstream API change awareness relevant. | [Pipedream documentation](https://pipedream.com/docs) |
| Cal.com | Its official payments page describes a Stripe integration and Stripe app used for paid booking events. | A focused public payment-integration surface supports a narrowly scoped question about upstream billing-change review. | [Cal.com Payments](https://cal.com/features/payments) |
| Voiceflow | Its official changelog identifies Twilio among supported telephony providers and documents product changes that affect voice runtime behavior. | A voice platform with public telephony-provider change history is a relevant conversation about evidence and release-review ownership. | [Voiceflow Changelog](https://docs.voiceflow.com/changelog/changelog) |
| Zapier | Its official Stripe–Twilio page publishes a broad set of Stripe event triggers together with Twilio call, SMS, WhatsApp, and other operations. | It is a relevant platform-design conversation about whether an evidence-first signal can help maintain a large integration surface. | [Zapier Stripe + Twilio](https://zapier.com/apps/stripe/integrations/twilio) |
| Tray.ai | Its official connector page describes Stripe payment events triggering Twilio SMS, voice, or WhatsApp flows, and discusses webhook retry behavior. | The documented webhook and retry surfaces make a concrete, narrow discussion about provider-change review appropriate. | [Tray.ai Twilio + Stripe](https://tray.ai/connectors/twilio-stripe-integrations/) |
| MESA | Its official page documents Stripe payment/subscription event workflows and Twilio notifications for Shopify automation. | Its small, provider-connected workflow surface is suitable for a design-partner conversation about low-noise change awareness. | [MESA Stripe + Twilio](https://www.getmesa.com/apps/stripe/integrate/twilio) |

The ten messages in the companion outreach draft consist of **eight companies and ten role-addressed conversations**: two distinct role hypotheses are prepared for Pipedream and Activepieces because both expose a public component or community-maintenance surface in addition to their platform engineering surface. All eight represented companies now have an official page opened or extracted during this research pass.
